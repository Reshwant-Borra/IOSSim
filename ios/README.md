# IOSSim On-Device DVT POC

Status: EXPERIMENTAL.

This folder is the iPhone-side proof-of-concept implementation. It is separate from the stable Mac-hosted IOSSim app in `backend/` and `frontend/`.

Runtime target:

```text
Mac once -> imported RPPairing -> Mac off -> LocalDevVPN route -> raw RPPairing tunnel -> RSD/DVT -> LocationSimulation
```

It intentionally does not implement IOSSim product UI, maps, Drive, GPX import, account features, a custom VPN, WLOC, or remote Mac control.

Canonical architecture and validation status live in [../docs/iphone_on_device_dvt/ARCHITECTURE.md](../docs/iphone_on_device_dvt/ARCHITECTURE.md). Historical research remains in [../docs/iphone_on_device_dvt/README.md](../docs/iphone_on_device_dvt/README.md).

## What Is Implemented

- Semantic RPPairing plist validation:
  - `public_key`: 32 bytes
  - `private_key`: 32 bytes
  - `identifier`: non-empty string
  - `alt_irk`: optional 16 bytes
- Keychain storage using `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`.
- Redacted pairing diagnostics.
- LocalDevVPN route/interface probe.
- TCP probe for `10.7.0.1:49152`.
- `IdeviceOnDeviceTunnelClient` bridge boundary for the pinned `jkcoxson/idevice` FFI call chain.
- Core Location observer recording coordinate, timestamp, accuracy, `isSimulatedBySoftware`, and `isProducedByAccessory`.
- E2 repeated-coordinate diagnostic harness.
- A bare SwiftUI app shell with:
  - `IMPORT RPPAIRING`
  - `RUN DIAGNOSTICS`
  - `CONNECT`
  - `SET TEST LOCATION`
  - `RUN 50 CHANGES`
  - `CLEAR SIMULATION`
  - `DISCONNECT`

## Dependency Boundary

The repo does not currently commit the `idevice` static library or XCFramework. SwiftPM builds use the fallback `IDEVICE_BRIDGE_UNAVAILABLE` path. The checked-in Xcode app target defines `IOS_SIM_IDEVICE_FFI` and requires the real pinned library at `Vendor/idevice/lib/libidevice_ffi.a`.

```text
repo: https://github.com/jkcoxson/idevice
commit: c442bd235bd14d6d5c8f28f85c9e6179e3a4c3d5
license: MIT
features needed: remote_pairing, rsd, dvt, device_info, core_device_proxy/tunnel support
```

The required FFI calls are isolated in `Sources/IOSSimOnDeviceDVTPOC/DvtLocationClient.swift`.

Build scripts live in `scripts/`. Generated Rust source/build output is under `.build/` and the generated static library is `Vendor/idevice/lib/libidevice_ffi.a`; both are ignored and must not be committed.

Build the local ignored library artifact with:

```bash
cd ios
./scripts/build_idevice_ios.sh
./scripts/verify_idevice_symbols.sh
```

Then build the physical-device app target:

```bash
xcodebuild -project IOSSimOnDevicePOC.xcodeproj \
  -scheme IOSSimOnDevicePOC \
  -configuration Debug \
  -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  build
```

## External Runtime Prerequisites

- Developer Mode enabled on the iPhone.
- An imported RPPairing file generated by a compatible Mac-side tool.
- External LocalDevVPN active for the first POC.
- Full Xcode and a signing team to build/install the iOS app.
- Accepted Xcode license.
- Rust toolchain with `rustup`/`cargo`.

No real RPPairing file should be committed, logged, uploaded, or placed outside ignored paths.

The POC app itself has built and installed with a free Personal Team. Self-building LocalDevVPN with a free Personal Team failed because Apple does not expose the required Network Extension/Personal VPN capabilities to Personal development teams.

## Local Software Verification

```bash
cd ios
swift build
swift run POCUnitChecks
```

The local checks do not prove the hardware architecture. They only verify parser/storage/probe/state behavior and the no-FFI bridge error path.
