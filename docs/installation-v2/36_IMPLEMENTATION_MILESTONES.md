# Implementation milestones

Milestones are dependency-ordered. Every gate is required; a failure leaves the preceding milestone’s behavior available and blocks dependent work.

## M0 — Research and contract freeze

**Objective/why now:** accept 00–40, choose the DDI product decision owner, LocalDevVPN relationship, release architecture policy, and stable error/state contracts before code divergence. **Files:** docs only; create ADR acceptance record. **Untouched:** all production source. **Prerequisites:** stakeholder/security/legal review. **Steps:** resolve 39 blockers, version state/wire/manifest schemas, open tracked acceptance issues. **Tests:** documentation link/term lint. **Acceptance:** every product decision has owner/date and DDI ADR is resolved or explicitly prevents public-zero-Xcode work. **Failure/rollback:** keep architecture `NOT_READY`; edit docs, no code rollback. **Security/migration/physical:** threat model and migration reviewed; no physical work.

## M1 — Release truth and build unification

**Objective/why now:** prevent testing or shipping the wrong bits before product work. **Files:** `iossim_cli.py`, `build_app.sh`, manifest models, release checks. **Untouched:** setup/pairing/runtime. **Prerequisites:** M0 architecture policy. **Steps:** one assembler, generated schema constants, output-derived manifest, actual architecture/hash/signature/SBOM audit, canonical naming; make direct script a wrapper. **Tests:** synthetic mismatches for architecture/schema/helper/payload/source; mounted app equality; local artifact audit. **Acceptance:** the current retest-style mismatch is rejected and two entry points yield identical app trees. **Failure:** no release-shaped output. **Rollback:** retain old dev build only under explicit nonrelease name. **Security:** signed manifest and dependency notices. **Migration:** none. **Physical:** final Developer ID/notarization deferred to M15.

## M2 — Hermetic tests and production-engine boundary

**Objective/why now:** restore trustworthy feedback and prevent live-state leakage. **Files:** `IOSSimMacApp`, `SetupStore`, engine protocols/fakes, all failing Mac tests, source checks. **Untouched:** device protocols and runtime behavior. **Prerequisites:** M1 component identity contract. **Steps:** inject stores/clocks/Apple/Keychain/device; implement complete fake protocol; production-only composition; remove stale Xcode expectations; fix fixtures so faults occur. **Tests:** all 279 tests pass or explicitly skipped with reason; safe source checks. **Acceptance:** no test reads user Application Support/UserDefaults/Keychain or contacts Apple/device; zero unexpected failures. **Failure:** block every later milestone. **Rollback:** source-only revert. **Security:** prevents test credential/device access. **Migration/physical:** none.

## M3 — Keyed state, journal, lease, and legacy import

**Objective/why now:** make all later mutations crash- and process-safe. **Files:** state/artifact stores, models, provisioner composition, SetupStore adapter. **Untouched:** Apple protocol, bridge, pairing wire, runtime. **Prerequisites:** M2 hermetic harness; schema 5 frozen. **Steps:** SetupKey layout, OS lock/lease, journal/CAS/snapshot, keyed profile store, schema-4 importer/quarantine. **Tests:** two-process contention, generation conflict, kill/fault at each write, corruption/downgrade, multi-team/device fixtures. **Acceptance:** one mutation per SetupKey and deterministic recovery with no lost last-good state. **Failure:** no migration promotion. **Rollback:** read old singleton and remove unpromoted candidate only. **Security:** permissions/path containment/profile privacy. **Migration:** explicit dual-read/single-write window. **Physical:** reboot/power recovery in M15.

## M4 — Helper protocol, integrity handshake, and errors

**Objective/why now:** make the process boundary deterministic before adding device APIs. **Files:** `IOSSimSetupEngine`, `BundledProvisioningEngine`, provisioner main, doctor/status/error models, SetupWizard. **Untouched:** domain mechanics. **Prerequisites:** M1 manifest, M3 store. **Steps:** protocol-info, V2 envelopes, bounds/timeouts/cancel, stable errors, strict environment, typed action states; remove “doctor” root wording. **Tests:** missing/tampered/wrong-schema/helper-crash/malformed-output cases. **Acceptance:** each fault yields the specified code without mutation. **Failure:** reinstall guidance only. **Rollback:** protocol v1 read-only fallback for migration release if signed/compatible. **Security:** signature/hash and environment controls. **Migration:** version negotiation. **Physical:** clean installed app handshake in M15.

## M5 — Initial USB Lockdown trust

**Objective/why now:** close the first fresh-device gap needed by every downstream device step. **Files:** C header, Rust bridge, Swift bridge/device trust service, models/tests. **Untouched:** RemotePairing and runtime. **Prerequisites:** M4 protocol; pinned idevice pair feature. **Steps:** exact `(UDID,mux ID,type)` selection fix; pair begin/poll/save/session validate; user-action mapping; bounded cancellation. **Tests:** fake pending/passcode/denied/save/validate/duplicate-device ordering and ABI memory tests. **Acceptance:** synthetic state machine and exact-handle enforcement pass. **Failure:** retain existing-record-only behavior with typed USB trust required. **Rollback:** ABI v1 remains readable during transition. **Security:** preserve Trust UI; no trust bypass or record export. **Migration:** reuse existing pair records. **Physical:** full initial-trust matrix before M15 acceptance.

## M6 — Developer-support provider boundary

**Objective/why now:** isolate the architecture blocker without contaminating mount logic. **Files:** DeveloperSupportCoordinator, NativeDeveloperServicesCoordinator, state/manifest/error models. **Untouched:** Apple auth, pairing, runtime. **Prerequisites:** M0 DDI decision; M3 store; M5 trust. **Steps:** retain ExistingAppleCacheProvider; implement exact BuildIdentity/provenance/cache interface; add approved provider only per accepted ADR; TSS/mount/service receipts. **Tests:** signed fixture, wrong build/hash/source, cache quota, TSS/mount/service failures. **Acceptance:** no unapproved URL/path can supply production assets; fresh fixture flow reaches RSD. **Failure:** `VEYA-DEVSERVICE-002`, no fallback mirror. **Rollback:** last verified content-addressed cache. **Security/legal:** signature/hash/rights metadata and no asset bytes in support. **Migration:** import existing caches read-only. **Physical:** fresh empty-cache matrix is mandatory and blocking.

## M7 — Native installation and AppService hardening

**Objective/why now:** make current implementation receipt-driven and remove selection ambiguity. **Files:** NativeApplicationManagement, NativeDeveloperServicesCoordinator, Swift/Rust bridge, provisioner. **Untouched:** pairing/rich runtime internals. **Prerequisites:** M5/M6. **Steps:** exact handle on every call; staged install/upgrade inventory receipt; DDI/tunnel/RSD/AppService boundaries; bounded reconnect; delete production devicectl route after parity. **Tests:** fault/inventory/service receipts and source scans. **Acceptance:** main and runner install/launch only through native graph in packaged build. **Failure:** preserve prior installed version and typed domain state. **Rollback:** reinstall previous signed artifact if still valid. **Security:** path/bundle/identity allowlists. **Migration:** reconcile existing installed apps. **Physical:** native AppService launch of both apps from canonical artifact.

## M8 — RemotePairing staged replacement

**Objective/why now:** remove a current security/rollback defect before declaring runtime readiness. **Files:** RemotePairingLifecycle, AutomaticPairingInbox, phone root, bridge proof APIs, stores/wire models. **Untouched:** DvtLocationClient scheduling. **Prerequisites:** M3 journal, M7 developer-service path. **Steps:** wire schema 2, request-specific bootstrap/AAD, active/candidate Keychain slots, possession challenge, RSD operational proof, two-sided promotion/recovery. **Tests:** crypto vectors, replay/wrong identity/expiry, no-op-proof regression, crash at each phase, property tests. **Acceptance:** copied receipt cannot pass; old active record survives every candidate failure. **Failure:** candidate removed, active retained. **Rollback:** explicit journal recovery. **Security:** highest-risk review/penetration analysis. **Migration:** schema-1 record becomes active only after reproof. **Physical:** first delivery and forced repair matrix.

## M9 — LocalDevVPN lifecycle

**Objective/why now:** turn external dependency into an owned compatibility flow. **Files:** coordinator, phone inbox/root, compatibility manifest, UI/errors. **Untouched:** VPN provider binary/config implementation. **Prerequisites:** M7 launch and M8 pairing. **Steps:** inventory/version state, App Store action, scene-active request replay, approval states, authenticated endpoint and developer-service proof. **Tests:** missing/unsupported/stale/replay/foreground/timeout fakes. **Acceptance:** receipt alone or bare stale TCP endpoint cannot yield ready. **Failure:** preserve pairing and display exact user action. **Rollback:** none beyond request cleanup. **Security:** request binding and no VPN secret export. **Migration:** accept current app only if version in matrix. **Physical:** install/approval/denial/update/reboot.

## M10 — Apple Personal Team adapter and signing lifecycle

**Objective/why now:** harden private behavior after state safety exists and before renewal qualification. **Files:** PersonalTeam service/adapter, live implementation, signing resolver, artifact provisioner, Keychain abstractions. **Untouched:** SetupStore protocol detail and runtime. **Prerequisites:** M2 fakes, M3 state, M4 errors. **Steps:** versioned adapter, fixture parsers, kill switch, typed taxonomy, read-before-create, candidate cert/key/profile renewal and scoped cleanup. **Tests:** offline response fixtures for all taxonomy; ambiguous mutation reconciliation; mocked Keychain; opt-in isolated integration only. **Acceptance:** SetupStore imports no private protocol types and no transient error duplicates resources. **Failure:** preserve existing apps/resources and disable mutations on incompatibility. **Rollback:** select prior adapter only if signed compatibility matrix permits. **Security:** credential lifecycle/host allowlists/ACL review. **Migration:** preserve tagged keys/certs. **Physical:** account/limits/expiry/ACL matrix.

## M11 — Runtime operational readiness

**Objective/why now:** make READY truthful after prerequisites are reliable. **Files:** RuntimeProvisioningSupport, ConsumerArtifactProvisioner, DvtLocationClient proof hook, runner mapping, state models/UI. **Untouched:** scheduler/location semantics except safe probe. **Prerequisites:** M7–M10. **Steps:** AppService runner launch, TestManager attach, one-writer generation, bounded Rich set/observe/clear proof, TTL/invalidation, pending Clear recovery. **Tests:** fake stage failures, writer conflict, clear/disconnect, cadence regression, fallback. **Acceptance:** stored checkpoints alone never yield READY; proof success produces identity-bound receipt. **Failure:** typed owning stage and Clear attempt. **Rollback:** restore last stable runtime session, never replay motion. **Security:** no coordinates in logs. **Migration:** old READY becomes `CONFIGURED_UNVERIFIED`. **Physical:** full Spoof/Drive matrix.

## M12 — Diagnostics and support schema 8

**Objective/why now:** make new complexity supportable before field qualification. **Files:** SupportBundleExporter, event DTOs, About panel, secret scanner. **Untouched:** domain resource bytes. **Prerequisites:** stable errors/receipts M4–M11. **Steps:** allowlist DTO, per-export aliases, release identity, scanner/abort, retention cleanup. **Tests:** inject every forbidden secret/profile/pairing/raw ID/coordinate and assert absence/abort; golden useful bundle. **Acceptance:** structural allowlist and negative scanner pass. **Failure:** no bundle emitted. **Rollback:** retain minimal in-app code/correlation display, never use schema 7 broad export. **Security:** privacy review. **Migration:** readers identify schema. **Physical:** support export for every lab failure.

## M13 — Canonical release/publish authority

**Objective/why now:** produce one reviewable candidate after function is complete. **Files:** release tooling/config/docs/update metadata. **Untouched:** product protocols. **Prerequisites:** M1 and M2–M12 gates. **Steps:** universal builds (or revise ADR), sign/notarize/staple, mount audit, signed manifest/SBOM, GitHub draft upload/redownload verify, update metadata. **Tests:** intentional mismatch suite plus reproducibility comparison. **Acceptance:** canonical filename/release ID and all actual-byte gates pass; no competing public artifact. **Failure:** draft remains unpublished. **Rollback:** publish new audited rollback build, never overwrite. **Security:** release keys/notary/update signature. **Migration:** release compatibility ID. **Physical:** final artifact install on clean Macs.

**Objective/why now:** brand only a qualified engine and preserve installed users. **Files:** product resources/plists/config, state migrator, manifests/update UI, optional bundle-ID provisioning. **Untouched:** runtime behavior. **Prerequisites:** M13 release pipeline and explicit bundle-ID decision. **Steps:** compatibility IOSSim release, display-name migration, state/Keychain aliases, dual-ID only if approved, signed receipt/rollback. **Tests:** fixtures from historical states/artifacts and downgrade block. **Acceptance:** no duplicate Apple identity, lost pairing, or unverified app removal. **Failure:** remain IOSSim-branded. **Rollback:** last compatible IOSSim app/state. **Security:** designated requirements/Keychain ACL. **Physical:** upgrade/reinstall matrix.

## M15 — Automated regression and physical qualification

**Objective/why now:** convert implementation confidence into shipment evidence. **Files:** test harness, lab manifests/results, no product change except proven fixes. **Untouched:** scope expansion/features. **Prerequisites:** all prior gates and DDI resolution. **Steps:** run safe CI, release audit, entire 33 matrix on final signed candidate, triage/fix/rebuild/repeat affected cells. **Tests:** all automated and physical cells. **Acceptance:** zero unexplained failures, no skipped release gate, evidence bound to final DMG hash. **Failure:** do not publish/market READY or zero-Xcode. **Rollback:** candidate revoked; previous release remains. **Security/migration:** final adversarial/privacy/migration sign-off. **Physical:** this milestone is the physical proof.
