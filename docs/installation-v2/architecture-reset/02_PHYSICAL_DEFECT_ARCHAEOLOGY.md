# Physical defect archaeology

## Method and limits

Sources were ranked: current source and raw diagnostics; contemporaneous physical reports/support evidence; screenshots whose visible content matches their label; artifact ledgers; old summaries; filename-only claims. Builds 1-3 have formal reports. Builds 4-7 are reconstructed from diagnostics, screenshots, local artifact identity, and later comments. Builds 8-11 have artifact history and diagnostics, but the ledger was not kept current. A row marked `INFERRED` is not promoted to physical observation.

| 8 | signing metadata login-Keychain prompt and codesign access prompt | metadata moved to files; key recovery | high visual |
| 9 | ChangeACL SecurityAgent prompt | removal of reuse-time ACL mutation | high visual |

| 11 | failure still before `KEYPAIR_CREATED` | architecture reset | high bound, exact API unknown |

The sequence did not validate one fixed build end-to-end. It serially revealed the next reachable unqualified boundary. A “new later failure” was often treated as evidence that the previous local patch was right, but many failures were alternative manifestations of the same Keychain/signing and state-recovery architecture.
