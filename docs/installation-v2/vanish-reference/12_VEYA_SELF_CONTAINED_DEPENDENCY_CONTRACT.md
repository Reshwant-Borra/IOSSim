# Veya self-contained dependency contract

Installation dependencies must be bundled, macOS-provided, Apple-service-provided through an explicit flow, phone-provided, or declared as a consumer prerequisite. Release fails for an undeclared dependency.

| Name | Source/owner | Verification/version/license | Update/offline behavior | Failure behavior |
| --- | --- | --- | --- | --- |
| Veya.app/helper | Veya release | nested signature, hash, team, schemas, protocol compatibility; Veya license | atomic signed app update; works offline except services | `VEYA-INTEGRITY-001..019`; refuse helper execution |
| native device bridge | bundled Rust dylib/static component | actual Mach-O architectures, ABI, hash, pinned idevice MIT notice/SBOM | ships with app; no runtime download | integrity/compatibility failure, no fallback to repo/devicectl |
| idevice dependencies | bundled/resolved at build | lockfile, SBOM, license policy, reproducible revision | updated only by reviewed release | fail build/release for unknown dependency |
| macOS system tools | supported macOS (`codesign`, Keychain/Security, usbmux transport) | startup capability probe on minimum supported OS | OS-owned | named unsupported-OS/system-capability error |
| Apple account/developer services | Apple network services through private adapter | adapter version, response schema, TLS/system trust; Apple terms govern | online required for auth/renewal; existing valid state may work offline | typed outage/auth/protocol errors and kill switch |
| signing key/certificate | Veya-generated key in user Keychain + Apple certificate | SecIdentity key/cert/team/expiry/access probe | candidate renewal before expiry; offline reuse while valid | preserve active identity; never silently delete |
| profiles | Apple Developer Services | CMS, team, App ID, UDID, entitlements, dates, hash | staged refresh; valid cached profiles reusable offline | profile-specific error; no install with invalid profile |
| source payloads | bundled DeviceArtifacts | release-manifest hash, bundle structure, declared IDs/schemas | immutable per release | integrity failure before signing |
| prepared artifacts | generated in protected temp workspace | recursive code/profile/entitlement validation | ephemeral; rebuilt on failure | delete candidate workspace; retain installed good version |
| initial pair record | generated by Lockdown after user Trust | selected UDID/BUID/session validation; sensitive | OS/Veya managed; reusable; repair only after invalid | `VEYA-TRUST`; never export in support bundle |
| personalized DDI inputs | **provider undecided** | exact build identity, hashes/signature/provenance/rights, provider version | online first use; verified cache offline; revocation policy required | `VEYA-DEVSERVICE-02x`; no unapproved mirror fallback |
| Apple TSS personalization | Apple service + phone nonce/IDs | response/device/build binding | online when new manifest required; cache only when valid | retry outage; reject mismatch |
| RemotePairing state | Mac native bridge + phone app | request-bound AEAD, challenge, developer-service proof | staged rotation; active state remains through failure | candidate rollback and typed pairing errors |
| LocalDevVPN | external App Store app `com.jkcoxson.LocalDevVPN` unless decision changes | bundle/version inventory, Apple install receipt where available, authenticated endpoint | App Store updates; offline after installed/configured | explicit missing/version/permission/runtime states |
| iPhone main/runner | Veya source payloads signed for team/device | post-install inventory, profile/team/hash/version | staged reinstall/renewal | do not remove unrelated/wrong-team app without consent |
| release metadata/update | one chosen authority; proposed GitHub Releases | manifest signature, artifact hash, version/build/commit/channel | cached current app remains usable; update is fail-safe | `VEYA-UPDATE`; never accept ambiguous filename/latest |

The unresolved DDI row prevents a final self-contained shipping contract. Vanish's mirror is documented evidence, not an implicit dependency Veya may inherit.

Release packaging follows Apple's [Packaging Mac software for distribution](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution). VPN ownership and consent must remain compatible with [TN3134: Network Extension provider deployment](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment).
